# 13. PSR и Composer

PSR — это рекомендации PHP-FIG, благодаря которым код из разных проектов стыкуется без переходников. Composer — менеджер зависимостей, который делает стыковку практической.

Код главы: `course/code/Ch13/`.

```bash
php course/code/Ch13/run.php
```

## PSR-1 и PSR-12: как выглядит код

PSR-12 (и его предок PSR-2) описывает оформление: четыре пробела вместо табов, открывающая скобка класса на новой строке, у метода — тоже, `declare(strict_types=1)` сразу после `<?php`, импорты через `use` по одному на строку, порядок модификаторов `final public static`.

Спорить об этом бессмысленно и незачем: выигрыш не в конкретных правилах, а в том, что весь PHP-мир пишет одинаково. Настройте автоформат в PHPStorm (Settings → PHP → Code Style → Set from → PSR-12) и забудьте.

PSR-1 добавляет базовое: один файл — либо объявления, либо побочные эффекты, но не то и другое; классы в `StudlyCaps`, методы в `camelCase`, константы капсом.

## PSR-4: имя класса = путь к файлу

Это тот самый стандарт, на котором держится автозагрузка курса:

```json
{
    "autoload": {
        "psr-4": {
            "Course\\": ""
        }
    }
}
```

Префикс `Course\` отображается на каталог `course/code`, дальше пространство имён повторяет структуру каталогов: `Course\Ch13\ConsoleLogger` → `Ch13/ConsoleLogger.php`. Отсюда правило «один класс — один файл» и требование к регистру: на Linux `consoleLogger.php` не найдётся, а на macOS найдётся, и это классический баг «у меня работает».

Файл `course/code/autoload.php` реализует ту же схему в двадцати строках — чтобы примеры запускались до того, как вы дойдёте до Composer. Обе схемы взаимозаменяемы:

```bash
composer -d course/code dump-autoload
```

После этого можно подключать `course/code/vendor/autoload.php` и получать те же классы.

## Интерфейсные PSR: PSR-3 и родня

Самое полезное в PSR — общие интерфейсы. PSR-3 описывает логгер, PSR-7 и PSR-15 — HTTP-сообщения и middleware, PSR-11 — контейнер, PSR-14 — диспетчер событий, PSR-18 — HTTP-клиент. Смысл один: ваш код зависит от интерфейса, а конкретная библиотека подставляется снаружи.

В примере главы `Logger` написан по мотивам PSR-3 (в реальном проекте вы просто подключите `psr/log`):

```php
interface Logger
{
    /** @param array<string, string|int> $context */
    public function log(LogLevel $level, string $message, array $context = []): void;
}
```

Две детали, которые стоит перенять у PSR-3.

**Сообщение с плейсхолдерами.** `'Добавлен {title}, всего {count}'` плюс контекст-массив вместо склейки строк. Сообщение остаётся постоянным — по нему можно группировать записи в хранилище логов, а значения лежат отдельно.

**Null-объект.** `NullLogger` реализует интерфейс и ничего не делает. Благодаря значению по умолчанию `private readonly Logger $logger = new NullLogger()` (значения по умолчанию в виде `new` разрешены с PHP 8.1) сервис никогда не проверяет `$logger` на `null`. Ветвление исчезло.

В `run.php` один и тот же `PlaylistService` работает с болтливым логгером, с логгером уровня `error` и с заглушкой. Код сервиса при этом не меняется — это глава 7, доведённая до стандарта, общего для всей экосистемы.

## Composer: минимум, который нужен всегда

`composer.json` курса — рабочий пример:

```json
{
    "require": { "php": ">=8.2" },
    "require-dev": { "phpunit/phpunit": "^10.5" },
    "autoload": { "psr-4": { "Course\\": "" } },
    "scripts": { "test": "phpunit", "lint": "php Ch15/check.php" }
}
```

- `require` — то, без чего код не работает в бою; `require-dev` — инструменты разработки (тесты, анализаторы). На сервере ставят `composer install --no-dev`.
- `^10.5` — «не ниже 10.5, но младше 11». Это семантическое версионирование: мажорная версия меняется при ломающих изменениях. `~10.5` строже (до 11 не пустит только по минорной), точная версия `10.5.3` обычно избыточна.
- `composer.lock` фиксирует точные версии всего дерева зависимостей. Его коммитят для приложений; `composer install` ставит ровно из lock, `composer update` пересчитывает и обновляет lock. Разница между этими двумя командами — самая частая причина «на сервере другая версия».
- `scripts` — короткие имена для длинных команд: `composer test` вместо полного пути к бинарнику.

Ещё пара команд, которые пригодятся: `composer require vendor/package` (добавить), `composer why vendor/package` (кто это притащил), `composer validate` (проверить файл), `composer dump-autoload -o` (оптимизированная карта классов для продакшена).

## Упражнение

1. Добавьте `MemoryLogger`, складывающий записи в массив, и напишите в `run.php` проверку: после трёх вызовов `add()` в нём две записи уровня `info` и одна `warning`.
2. Добавьте декоратор `PrefixedLogger`, который дописывает к сообщению префикс и передаёт вызов дальше (глава 9 в новом контексте).
3. Выполните `composer -d course/code dump-autoload`, затем замените в своей копии `run.php` подключение `../autoload.php` на `../vendor/autoload.php` и убедитесь, что всё работает.
4. Откройте `course/code/composer.json` и добавьте скрипт `"ch13": "php Ch13/run.php"`. Запустите `composer -d course/code ch13`.
