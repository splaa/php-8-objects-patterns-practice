# 11. Слой приложения коротко

Эта глава — про две идеи, которые лежат в основе любого PHP-фреймворка: единая точка входа и общее место для сервисов. Мы разбираем идеи, а не пишем фреймворк: в реальном проекте возьмите готовый.

Код главы: `course/code/Ch11/`.

```bash
php course/code/Ch11/run.php
```

## Front Controller: одна дверь в приложение

Без него у каждого скрипта своя обвязка: подключить автозагрузку, собрать зависимости, проверить права, поймать ошибку. Обвязка расползается и разъезжается.

Front Controller собирает это в одну точку:

```php
public function handle(Request $request): string
{
    $command = $this->resolver->resolve($request);

    try {
        return sprintf('[%s] %s', $command::class, $command->run($request, $this->registry));
    } catch (Throwable $e) {
        return sprintf('[500] %s: %s', $command::class, $e->getMessage());
    }
}
```

Всё общее живёт здесь: разрешение маршрута, обработка исключений, а в настоящем приложении ещё логирование, авторизация, таймеры. В последней строке примера сервис не зарегистрирован, но пользователь видит аккуратный `[500]`, а не трассировку — потому что обработка ошибок в одном месте.

Разрешение маршрута вынесено отдельно:

```php
return match ($request->path) {
    '/playlist' => new ShowPlaylist(),
    '/playlist/add' => new AddTrack(),
    default => new NotFound(),
};
```

`CommandResolver` — единственное место, где строка пути превращается в объект. Никаких `include` по имени файла из запроса: набор действий закрыт, и неизвестный путь честно получает `NotFound`. Захотите таблицу маршрутов из конфигурации — поменяете один класс.

Каждое действие — объект с одним методом (`AppCommand`), это Command из главы 10 в масштабе приложения. Команда не знает, откуда пришёл запрос и куда уйдёт ответ: она получает `Request`, возвращает строку. Потому её легко вызвать из теста.

## Registry: общее место для сервисов

Приложению нужны репозитории, соединения, конфигурация. Создавать их в каждой команде — дублирование, тянуть через глобальные переменные — хаос. Registry — объект, который хранит уже созданные сервисы:

```php
$registry = new Registry();
$registry->set(new PlaylistRepository());
```

Дальше он передаётся в команды, и они берут нужное: `$registry->get(PlaylistRepository::class)`. Ключом служит имя класса — это даёт статическому анализатору и PHPStorm понять тип возвращаемого объекта (аннотация `@template` в коде именно для этого).

Три вещи, которые делают Registry терпимым, а не вредным.

**Он не статический.** В книжном варианте реестр часто делают синглтоном; мы сознательно оставили обычный объект. В тесте создаётся второй реестр с дублёрами, и тесты не влияют друг на друга.

**Он создаётся в одной точке сборки.** Всё, что нужно приложению, регистрируется в `run.php` — аналоге `index.php` или `bin/console`. Остальной код не создаёт сервисы, а получает.

**Он не заменяет конструктор.** Команда получает реестр только потому, что резолвер создаёт команды заранее и не знает, кому что понадобится. Обычные доменные классы должны принимать конкретные зависимости конструктором — это глава 7. Реестр, просочившийся вглубь доменного кода, — это скрытые зависимости и шаг назад к синглтону.

Следующий эволюционный шаг — DI-контейнер: он не только хранит готовые сервисы, но и создаёт их по описанию, разрешая зависимости сам. Интерфейс для такого контейнера стандартизован как PSR-11 (`ContainerInterface` с методами `get()` и `has()`), и почти все фреймворки его реализуют.

## Что важно унести

Единая точка входа и явная точка сборки — то, что отличает приложение от набора скриптов. Действия — маленькие объекты, зависимости — снаружи, ошибки — в одном обработчике. Когда вы дальше откроете Symfony или Laravel, вы увидите эти же два слоя, обросшие возможностями: роутер, контейнер, middleware.

## Упражнение

1. Добавьте действие `RemoveTrack` и маршрут `/playlist/remove`. `FrontController` менять нельзя.
2. Замените `match` в резолвере на таблицу `array<string, class-string<AppCommand>>`, передаваемую в конструктор. Что стало проще, что — опаснее?
3. Добавьте в `FrontController` замер времени: пусть ответ заканчивается на `(N мс)`. Ни одна команда при этом не меняется — в этом и смысл единой точки.
4. Напишите в `run.php` второй сценарий: новый `Registry` с пустым `PlaylistRepository`, те же запросы. Убедитесь, что два экземпляра приложения не мешают друг другу — со статическим реестром так не получилось бы.
