# 5. Типы PHP 8, которые нужны каждый день

Типы в PHP — не украшение и не подсказка для IDE. Это проверки, которые выполняются в рантайме, и документация, которая не врёт.

Код главы: `course/code/Ch05/`.

```bash
php course/code/Ch05/run.php
```

## `declare(strict_types=1)` — первая строка каждого файла

Без него PHP приводит типы «по-дружески»: строка `'215'` станет `int 215`, а `'215abc'` — тоже `215`, но с предупреждением. Со строгим режимом несовпадение типа аргумента или возврата даёт `TypeError` сразу:

```
TypeError: Course\Ch05\Track::__construct(): Argument #3 ($seconds) must be of type int
```

Важная деталь: `declare(strict_types=1)` действует на **вызовы, сделанные из этого файла**, а не на класс, который вы описали. Поэтому строку ставят в каждый файл, без исключений. Единственное послабление действует всегда: `int` принимается там, где ждут `float`.

## Nullable: `?Track` и `null`

Тип `?Track` означает «объект или ничего» и заставляет вызывающего подумать об отсутствии:

```php
public function find(int|string $id): ?Track
{
    return $this->tracks[$id] ?? null;
}
```

Метод `find()` честно допускает, что трека нет. Метод `get()` — не допускает: он либо вернёт трек, либо бросит исключение. Разделять такие пары полезно: вызывающий выбирает семантику, а не гадает по имени. Оператор `??` и присваивающий `??=` — ваш основной инструмент работы с nullable, `?->` — вызов метода, безопасный к `null`.

Не делайте `null` значением по умолчанию просто «чтобы было». Каждый `?` — это ветка в коде читателя.

## Union: `int|string`

Составной тип перечисляет допустимые варианты:

```php
public readonly int|string $id;
```

Так выглядит идентификатор, который в базе `int`, а в импортированном каталоге — строковый слаг. Union уместен, когда вариантов два-три и они равноправны. `int|string|array|null` — не тип, а капитуляция: такой параметр нужно разбивать на разные методы или заворачивать в собственный объект-значение.

Запустите пример и посмотрите на первые две строки вывода: `find('1')` и `find(1)` возвращают один и тот же трек. Это не магия union-типов, а правило ключей PHP-массива — числовые строки становятся `int`. Union разрешает передать оба варианта, но хранилище их склеило. Такие стыки нужно знать за собой.

## Продвижение свойств и `readonly`

```php
public function __construct(
    public readonly int|string $id,
    public readonly string $title,
    public readonly int $seconds,
    public readonly Quality $quality = Quality::Standard,
    public readonly ?string $lyrics = null,
) {}
```

Продвижение убирает ритуал «объявил свойство — присвоил в конструкторе». `readonly` (PHP 8.1) разрешает ровно одну запись — из области видимости класса. Вместе они дают неизменяемые объекты почти бесплатно, а неизменяемость снимает целый класс багов: объект нельзя испортить после того, как он прошёл валидацию.

Меняющиеся данные оформляют через «копию с изменением»:

```php
public function withQuality(Quality $quality): self
{
    return new self($this->id, $this->title, $this->seconds, $quality, $this->lyrics);
}
```

## Перечисления вместо строк-констант

```php
enum Quality: string
{
    case Low = 'low';
    case Standard = 'standard';
    case Lossless = 'lossless';

    public function bitrate(): int
    {
        return match ($this) {
            self::Low => 96,
            self::Standard => 256,
            self::Lossless => 1411,
        };
    }
}
```

`Quality` — полноценный тип: в сигнатуре нельзя передать `'losless'` с опечаткой. Backed-перечисление (`: string`) умеет `->value`, `Quality::from('low')` и `tryFrom()` для данных из внешнего мира. Методы внутри enum — нормальная практика: данные, зависящие от варианта, живут рядом с вариантом.

`match` по enum ещё и исчерпывающий: забыли новый case — получите `UnhandledMatchError` в рантайме, а статический анализатор скажет об этом раньше. Ради этого свойства мы во всём курсе пишем `match`, а не `switch`.

## `never`, `void`, `mixed`, `static`

`never` — функция не возвращает управление: всегда бросает исключение или завершает процесс.

```php
private function missing(int|string $id): never
{
    throw new RuntimeException("Трек {$id} не найден");
}
```

Благодаря этому строка `return $this->find($id) ?? $this->missing($id);` типизируется как `Track`: вторая ветка «не возвращает», значит, тип выражения определяет первая.

`void` — «возвращает управление, но без значения». `static` как тип возврата — «экземпляр вызванного класса»; именно он делает цепочки `->add()->add()` корректными для наследников. `mixed` — «что угодно»; это осмысленный тип ровно там, где значение действительно любое (сериализация, кеш, дампер). В доменном коде `mixed` почти всегда означает «я не додумал».

## Упражнение

1. Добавьте в `Track` метод `withLyrics(?string $lyrics): self` по образцу `withQuality()` и убедитесь, что исходный объект не изменился.
2. Добавьте в `Catalog` метод `totalSizeMb(): float` и метод `byQuality(Quality $quality): array` (только треки нужного качества).
3. Добавьте вариант `Quality::Hires` с битрейтом `4608`. Найдите все `match`, которые перестали быть исчерпывающими, и убедитесь, что PHP сообщает об этом сам.
4. Попробуйте передать `Quality::from('hi-res')` и поймайте `ValueError`, затем замените на `tryFrom()` и обработайте `null`.
