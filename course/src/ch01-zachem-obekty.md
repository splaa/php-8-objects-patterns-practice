# 1. Зачем объекты и как устроен курс

## Как проходить курс

Одна глава — одна сессия. Прочитали, набрали пример руками в PHPStorm, запустили, сделали упражнение, закрыли. Не читайте три главы подряд: объектный код усваивается пальцами, а не глазами.

Что нужно:

- PHP 8.4 или новее (`php -v`) — курс опирается на возможности этой версии, на 8.3 половина примеров не запустится;
- PHPStorm (или любой редактор, но дальше я упоминаю именно его). Сразу выставьте Settings → PHP → **PHP language level: 8.4**, иначе IDE подчеркнёт красным корректный код; там же Code Style → Set from → PSR-12;
- склонированный репозиторий курса — весь код примеров лежит в `course/code/`.

Все примеры запускаются из корня репозитория одной командой, например:

```bash
php course/code/Ch01/run.php
```

Автозагрузка классов настроена в `course/code/autoload.php` (PSR-4: `Course\ChNN\Foo` → `course/code/ChNN/Foo.php`). Тот же самый маппинг описан в `course/code/composer.json`, чтобы PHPStorm и Composer видели классы одинаково. Composer понадобится только в главах 13–15; до них примеры работают на голом PHP.

Сквозной пример один на весь курс — маленькая **медиатека**: трек, альбом, плейлист, плеер. Он будет расти вместе с вами: в главе 2 это один класс, к главе 12 — дерево плейлистов, события и хранилище. Ничего другого мы моделировать не будем, чтобы каждая новая идея ложилась на уже знакомые сущности.

## Зачем вообще объекты

Процедурный PHP отлично решает маленькие задачи. Проблемы начинаются, когда данные и правила работы с ними живут порознь.

Возьмём трек как ассоциативный массив: `['title' => 'Coastline', 'seconds' => 215]`. Чтобы показать длительность как `3:35`, нужна функция форматирования. Через месяц в проекте таких функций три, и у каждой своя копия правила. Ещё через месяц кто-то запишет `$track['secons'] = 300` — с опечаткой. PHP промолчит, массив послушно примет новый ключ, а ошибка всплывёт в другом месте и через неделю.

Объект закрывает обе дыры сразу. Правило форматирования лежит внутри класса, рядом с данными, которых оно касается, — это **связность**. Поля объявлены заранее и защищены модификаторами, поэтому опечатка в имени свойства или попытка изменить `readonly`-поле превращаются в ошибку немедленно.

Разберите пример:

```php
final class Track
{
    public function __construct(
        public readonly string $title,
        public readonly int $seconds,
    ) {
    }

    public function format(): string
    {
        return sprintf('%s (%d:%02d)', $this->title, intdiv($this->seconds, 60), $this->seconds % 60);
    }
}
```

Запустите:

```bash
php course/code/Ch01/run.php
```

В `run.php` есть строка `new Track('Coastline', 215)->format()`. В PHP 8.4 выражение `new` больше не нужно оборачивать в скобки, чтобы обратиться к методу созданного объекта; раньше писали `(new Track(...))->format()`. Мелочь, но дальше в курсе она встретится десятки раз.

Вывод показывает четыре факта. Массив и объект форматируются одинаково — объекты не «правильнее» сами по себе. Массив с опечаткой в ключе тихо остаётся прежним. Объект на попытку записи в `readonly`-свойство бросает `Error`. И самое важное: чтобы поменять формат длительности во всей системе, в объектной версии достаточно одного метода.

## Что объекты дают дальше

Три вещи, ради которых стоит терпеть лишний синтаксис:

**Единая точка изменения.** Поведение живёт там же, где данные. Меняете правило — меняете один класс.

**Подстановка.** Код, написанный против интерфейса `Playable`, работает и с локальным файлом, и с потоком, и с заглушкой в тесте. Переписывать вызывающий код не нужно — это основа и паттернов, и тестов.

**Явные границы.** `public` — договор с внешним миром, `private` — ваша кухня. Пока договор не меняется, внутри можно переписывать что угодно.

Ни одна из этих вещей не бесплатна. Класс на три строки, обёрнутый в фабрику, интерфейс и декоратор, — это не «хороший дизайн», а лишний шум. Дальше в курсе каждый паттерн идёт вместе с ответом на вопрос «какую конкретно боль он снимает»: если боли нет, паттерн не нужен.

## Карта курса

Главы 2–6 — язык: классы, наследование и композиция, интерфейсы, типы PHP 8, исключения. Глава 7 — словарь дизайна: сцепление, связность, зачем вообще паттерны. Главы 8–12 — паттерны: порождение, структура, поведение, слой приложения, работа с данными. Главы 13–15 — практика вокруг кода: PSR и Composer, тесты на PHPUnit, Git и автоматизация.

Каждая глава заканчивается упражнением. Решайте его до перехода к следующей: код следующей главы часто опирается на то, что вы написали руками.

## Упражнение

Скопируйте `course/code/Ch01/run.php` в свой файл и доработайте класс `Track`:

1. добавьте свойство `artist` (тоже `readonly`) и включите его в `format()` в виде `Artist — Title (3:35)`;
2. добавьте метод `isLongerThan(Track $other): bool`;
3. создайте три трека, выведите каждый и напечатайте название самого длинного.

Никаких массивов внутри решения. Если рука тянется к `array_map` по массиву массивов — это сигнал, что данные снова расползлись.
